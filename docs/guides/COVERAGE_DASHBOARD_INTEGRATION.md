# 📊 Live Coverage Dashboard Integration

**Last Updated:** November 1, 2025  
**Status:** ✅ Active - Integrated with development workflow

## 🎯 Overview

The Lokifi project now includes an **automatic live coverage dashboard** that runs alongside your development servers. Every time you start the full development stack, the coverage dashboard is automatically available at **http://localhost:3002**.

## 🚀 Quick Start

### Start Everything (Recommended)
Run the unified task that starts all services including the coverage dashboard:

**VS Code Command Palette (Ctrl+Shift+P / Cmd+Shift+P):**
```
Tasks: Run Task → 🚀 Start All Servers
```

This will start in sequence:
1. 🔴 Redis Server (Docker)
2. 🗃️ PostgreSQL Server (Docker)
3. 🔧 Backend Server (FastAPI on :8000)
4. 🎨 Frontend Server (Next.js on :3000)
5. 📊 Coverage Dashboard (Live dashboard on :3002)

### Individual Tasks
You can also start services individually:

- **🔴 Start Redis Server (Docker)** - Redis cache on :6379
- **🗃️ Start PostgreSQL Server (Docker)** - PostgreSQL database on :5432
- **🔧 Start Backend Server** - FastAPI on :8000
- **🎨 Start Frontend Server** - Next.js on :3000
- **📊 Start Coverage Dashboard** - Coverage dashboard on :3002
- **🛑 Stop All Servers** - Stops all Docker containers
- **🔄 Restart All Servers** - Full restart sequence

## 📊 Coverage Dashboard Features

### What It Shows
The dashboard (http://localhost:3002) provides:

- ✅ **Overall Coverage Percentage** - Frontend test coverage metrics
- 📈 **Trend Analysis** - Coverage changes over time
- 📁 **File-Level Breakdown** - Coverage per file/directory
- 🎯 **Protected Thresholds** - Ensures coverage doesn't drop
- 🔍 **Detailed Reports** - Line-by-line coverage visualization

### How It Works

**Initial Startup:**
1. Task checks if coverage data exists (`coverage-dashboard/data.json`)
2. If missing, automatically runs `npm run test:coverage` to generate initial data
3. Starts a local HTTP server on port 3002
4. Dashboard is immediately accessible in your browser

**Updates:**
The dashboard data is updated whenever you run:
```bash
cd apps/frontend
npm run test:coverage
```

The dashboard will automatically reflect the new coverage data on refresh.

## 💡 Pro Tips

### 1. Keep Dashboard Running
The dashboard is lightweight and can run continuously during development. It doesn't interfere with other services.

### 2. Monitor Test Quality
Use the dashboard to:
- Identify untested code paths
- Track coverage trends over time
- Ensure new features maintain coverage standards
- Spot coverage regressions before commits

### 3. Integration with Workflow
The dashboard integrates seamlessly with:
- **VS Code Tasks** - Starts automatically with "🚀 Start All Servers"
- **Test Runner** - Updates when you run `npm run test:coverage`

## 🛑 Stopping Services

### Stop All at Once
**VS Code Command Palette:**
```
Tasks: Run Task → 🛑 Stop All Servers
```

This stops:
- 🔴 Redis Docker container
- 🗃️ PostgreSQL Docker container

**Note:** Terminal-based servers (Backend, Frontend, Dashboard) should be stopped manually by pressing `Ctrl+C` in their respective terminals or closing the terminal tabs.

### Stop Individual Services
```bash
# Stop Docker containers
docker stop lokifi-redis
docker stop lokifi-postgres

# Stop terminal servers
# Press Ctrl+C in the respective terminal window
```

## 🔧 Troubleshooting

### Dashboard Shows "No Coverage Data"
**Solution:**
```bash
cd apps/frontend
npm run test:coverage
```
Then refresh http://localhost:3002

### Port 3002 Already in Use
**Solution:**
```bash
# Find and kill the process
Get-Process | Where-Object {$_.ProcessName -like "*node*"} | Stop-Process -Force

# Or change the port in tasks.json (line with "npx serve coverage-dashboard -l 3002")
```

### Coverage Data Not Updating
**Solution:**
1. Ensure tests are passing: `npm test`
2. Regenerate coverage: `npm run test:coverage`
3. Hard refresh browser: `Ctrl+Shift+R` / `Cmd+Shift+R`
4. Check `coverage-dashboard/data.json` was updated

### Docker Containers Not Starting
**Solution:**
```bash
# Check Docker is running
docker ps

# If not running, start Docker Desktop
# Then rerun the task
```
