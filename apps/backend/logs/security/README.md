# Backend Security Logs

**Purpose**: Security event logs, audit trails, and security scan reports.

## Current Files

- **security_events.log** - Application security events
  - Auto-generated by backend security middleware
  - Contains: Authentication attempts, authorization failures, suspicious activity
  - Monitored by: Security monitoring systems

## Log Types

### Application Security Events
- Authentication failures
- Authorization denials
- Rate limiting triggers
- Suspicious request patterns
- JWT token validation failures

### Dependency Security Scans
```bash
# pip-audit (Python dependency vulnerabilities)
pip-audit > logs/security/pip-audit-$(date +%Y%m%d).log

# Bandit (Python security linter)
bandit -r app/ > logs/security/bandit-report.txt

# Safety (Python dependency checker)
safety check > logs/security/safety-report.txt
```

### Security Headers & CORS Logs
- CORS policy violations
- Content Security Policy (CSP) violations
- X-Frame-Options violations

## Monitoring

**Regular Security Checks** (recommended schedule):
- **Daily**: Review security_events.log for anomalies
- **Weekly**: Run pip-audit for new vulnerabilities
- **Monthly**: Full Bandit scan and report review
- **Before deployment**: Comprehensive security audit

## Alert Patterns

Watch for these patterns in security_events.log:
```
CRITICAL: Multiple failed login attempts from IP: xxx.xxx.xxx.xxx
WARNING: JWT token expired or invalid
ERROR: Unauthorized access attempt to admin endpoint
INFO: Rate limit exceeded for user_id: {id}
```

## Best Practices

1. **Retention**: Keep security logs for at least 90 days (compliance)
2. **Encryption**: Ensure logs are encrypted at rest (production)
3. **Access control**: Restrict log access to authorized personnel only
4. **Regular review**: Automated monitoring + manual periodic review
5. **Incident response**: Document security incidents with log references
