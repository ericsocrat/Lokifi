# Backend Logs Directory

**Purpose**: Organized storage for backend test coverage, security logs, pytest output, and performance profiling.

## Directory Structure

```
logs/
├── README.md           # This file
├── coverage/           # Pytest coverage reports (coverage.json, htmlcov/)
├── test/               # Pytest execution logs
├── lint/               # Ruff/Flake8 output files
├── security/           # Security event logs, audit logs
└── performance/        # API performance profiling, SQL query logs
```

## Usage Patterns

### Coverage Reports
```bash
# Generate coverage report
pytest --cov --cov-report=html --cov-report=json

# Files auto-generated:
# - logs/coverage/coverage.json
# - logs/coverage/htmlcov/index.html
```

### Test Logs
```bash
# Run tests with output log
pytest -v > logs/test/pytest-$(date +%Y%m%d).log 2>&1

# Run specific test with detailed output
pytest tests/test_auth.py -vv > logs/test/pytest-auth-$(date +%Y%m%d).log
```

### Lint Logs
```bash
# Ruff linting output
ruff check . > logs/lint/ruff-output.txt

# Flake8 output (if using)
flake8 . > logs/lint/flake8-output.txt
```

### Security Logs
```bash
# Security event logs (auto-generated by application)
# - logs/security/security_events.log

# Dependency audit
pip-audit > logs/security/pip-audit-$(date +%Y%m%d).log

# Bandit security scan
bandit -r app/ > logs/security/bandit-report.txt
```

### Performance Logs
```bash
# SQL query profiling
# Export slow query logs to logs/performance/

# API endpoint profiling
# Use cProfile or py-spy for performance analysis
```

## File Naming Conventions

**Timestamp-based** (Daily):
- `pytest-yyyymmdd.log` - Daily test runs
- `pip-audit-yyyymmdd.log` - Daily security scans

**Session-based** (Sprint work):
- `pytest-session{N}.log` - Sprint test tracking
- `coverage-session{N}.json` - Coverage evolution

**Feature-based** (Specific analysis):
- `pytest-auth-feature.log` - Feature-specific test logs
- `performance-api-baseline.txt` - Performance baselines

## Current Files

### Coverage
- `coverage.json` - Machine-readable coverage report (moved from backend root)
- `htmlcov/` - HTML coverage reports (moved from backend root)

### Security
- `security_events.log` - Application security events (moved from logs root)

## Retention Policy

**Keep**:
- Latest 7 daily test logs (weekly rotation)
- Latest coverage report (htmlcov/)
- All security logs (audit trail)
- Performance baselines (historical reference)

**Archive**:
- Older test logs → `.archive/` subdirectory
- Old coverage reports (keep latest only)

**Delete**:
- Test logs older than 30 days
- Temporary pytest cache files

## .gitignore Integration

All log files are automatically gitignored via:
```
logs/
*.log
coverage.json
htmlcov/
.pytest_cache/
__pycache__/
```

Coverage reports and baselines can be explicitly committed if needed for documentation.

## Best Practices

1. **Regular cleanup**: Run `pytest --cache-clear` to clean test cache
2. **Coverage tracking**: Compare coverage.json between sprints
3. **Security monitoring**: Review security_events.log regularly
4. **Performance baselines**: Keep before/after performance logs for optimization work
